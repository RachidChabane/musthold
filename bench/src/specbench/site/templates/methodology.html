Methodology

The benchmark gives real pull requests to a coding agent, stops it when it declares the work done, and gates the same change under each arm. A separate oracle, never shown to the agent or the gate, decides whether the change is defective.

Tasks and ground truth

Each task is a merged pull request of an open-source repository that adds a feature or changes a behaviour. A specification of observable criteria is written from the issue, the pull request description, the non-test diff and the public interface, never from a test. Specification, oracle and construction records stay sealed until the run.

  • U: the pull request's own added or modified tests; R: the pre-existing tests that pass before and after it. ${defect_rule} This human-written truth is the primary one.
  • H: per-criterion property and example tests written by an isolated session from the specification alone; X on U, H and R is a secondary figure.
  • O: upstream assertions about behaviour no criterion states. Their failures are reported as out-of-spec defects, never in X.

Trunks, stops and arms

One trunk is one task run by one harness. The trunk stops on tests alone. S_N is its first stop and S_T its first stop with passing tests; every arm is evaluated on the same S_T snapshot. Where an arm blocks, the session is branched from S_T and resumed with the gate's message, so each arm measures the gate in the loop, repairs included. The gate always runs in a clean room the agent cannot reach.
