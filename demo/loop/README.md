# The agent loop, recorded

This demonstration records one Claude Code session at work in a small project
equipped with [Shallnot](https://github.com/RachidChabane/shallnot) and the three
spec-proof modules. Nothing in the transcript is written by hand: the runner starts
the real CLI, the real gate and the real modules, records what they print, and
renders the records.

## What it shows

The project, [`fixture/boxoffice`](fixture/boxoffice), prices a cinema ticket from
the buyer's age. Its spec has four criteria in Shallnot's format, each with an
inline example. Three are implemented and tested; the session is asked to implement
the fourth (free entry under 3) and add a test for it.

One existing test is weak. The test of BOX-2 ("65 or older pays 8") cites the
criterion and passes, but it only checks age 70. Code that starts the senior price
at 66 breaks BOX-2, yet every test still passes.

What a run then shows, step by step:

1. The agent implements the task and says it is done.
2. Shallnot's end-of-turn hook holds the turn. The proofs of the changed code are
   missing, and the block message names the skill that produces them.
3. The agent runs `prove-all`. Blind executor subagents answer the modules' tickets.
4. Discriminating power finds a surviving mutant of BOX-2: a change that violates
   the criterion's example and passes every test. Alignment may escalate the test
   as well.
5. The gate blocks again. Its message names BOX-2, how the mutant was drawn and
   the input every test passes while the mutant fails it: the criterion's example
   `ticket_price(age=65) => 8`. It never shows the mutant's code. The transcript
   shows that message as the agent received it.
6. The agent strengthens the test and proves again, and the gate passes.

A run that goes another way is rendered the way it went: a gate that gives up, a
session stopped at its cap, a block the agent leaves.

## Files

| Path | What it is |
|---|---|
| `fixture/boxoffice/` | the project the session starts from |
| `demo.json` | the runs: task, arm, repetitions, seed, model, caps, permission rules |
| `run` | the front door: `build`, `test-containers`, `live`, `keep`, `replay` |
| `container/` | the engine, the Linux build of the product, the session image and its pinned base images |
| `recording/` | a kept recording and its rendered transcript, once a live run is kept |

The runner is `tools/canary/cmd/spec-proof-demo-loop`. It reuses the live canary's
credential, cap, lock and process-group code (`tools/canary`).

## Replay

Rendering needs no model, no network and no credential. It reads the recording and
writes `transcript.md` and `transcript.html` (a self-contained fragment) beside it:

```
demo/loop/run replay
demo/loop/run replay --check
```

`--check` writes nothing and fails when the committed transcript differs from what
the recording renders, so a published page can be regenerated byte for byte.

## Run it live

A live run spends the model quota of the account whose token it uses. It needs:

- [colima](https://github.com/abiosoft/colima) and the docker client, a Go
  toolchain, `npm`, and the Shallnot source that `script/shallnot-src` finds;
- a long-lived token from `claude setup-token`, stored in the macOS keychain as
  the generic password of service `spec-proof-claude-oauth` under your login, or
  set in `CLAUDE_CODE_OAUTH_TOKEN`.

Print what a run will do first. This starts nothing and reads no token:

```
demo/loop/run live --dry-run
```

Then run it:

```
demo/loop/run live
```

The run starts the demonstration's own engine, the colima profile
`spec-proof-loop` (2 CPUs, 3 GiB), which mounts only the work area and the product
tree. Every docker command goes through `container/docker`, which names that
engine's socket and an empty client configuration, never your current context.
The engine stops when the run ends. The run then builds:

- the product and Shallnot for Linux in the pinned Go image of `container/images`,
  into `.tools/demo-loop/product`;
- the pinned Linux Claude Code (`script/claude-code-install --linux`, the version
  in `script/claude-code.pin`), whose SHA-256 each run records;
- the session image, the pinned Python base with git and pytest.

It starts one session per run under `script/mem-guard`. A session starts only
when its time cap ends before 07:30 local time, checked before each session,
unless `--force-window` is given. The run directories go under
`.tools/demo-loop/work`, or under the directory `--work` names.

Nothing of the run executes on the host but the runner and the docker client.
Every step that touches the project, the preparation, the gate before and after,
and the diff, runs in a container that has:

- the user's uid, no capability, no new privilege and a read-only root;
- an empty scratch HOME on tmpfs;
- 2 CPUs and 2.5 GiB of memory;
- no network;
- the run directory mounted read-write and the product tree read-only;
- no docker socket and no SSH agent;
- an environment emptied by `env -i` and refilled from a fixed list.

The session's container has the same bounds on an internal network with no route
out. Its one exit is an egress proxy that forwards a CONNECT to
`api.anthropic.com:443` and refuses every other host, logging each request with
its decision into `records/egress.log`. The session runs with
`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`. The token is read on the host and
written to the container's entry on its standard input. The entry starts Claude
Code with the token in Claude Code's environment and its standard input closed,
so the token is in no command line and no container option. After the session the
runner scans every record for the token and for any text of a token's shape, and
a hit fails the run.

Each session gets:

- a fresh copy of the fixture, committed, then equipped with `shallnot init` and
  `init` and `enable` of each module;
- its own Claude Code configuration directory, in which the project is trusted;
- the caps of `demo.json`.

The process group of the session's docker client is ended at a cap, and the
session's and the proxy's containers are removed whatever the session did. The
records land in the run directory the command prints, with the transcript in
`records/transcript.md`.

To publish a run, keep it as the recording, then commit `demo/loop/recording`:

```
demo/loop/run keep <run directory>
```

`keep` writes the run directory, the repository root and your home directory as
`<run>`, `<repo>` and `~`. It scans every record for the token and for any text of
a token's shape first, and keeps nothing on a hit.

## The records

| File | Content |
|---|---|
| `run.json` | the run: task, arm, model, prompt, command line, caps, versions, session image, Claude Code SHA-256, egress allowlist, start, end, exit, why it was stopped |
| `setup.jsonl` | every preparation command with its exit code and output |
| `stream.jsonl`, `stream-times.jsonl` | the CLI's event stream and when each line arrived |
| `stderr.txt` | what the CLI printed to its error stream |
| `hooks.jsonl` | every hook call the shims saw, the gate's block messages included |
| `egress.log` | every request the session's container sent out, with the proxy's decision |
| `gate-before.json`, `gate-after.json` | Shallnot's report on the equipped project and on the project the session left |
| `change.diff` | the session's change against the equipped commit |

## A small benchmark

`demo.json` lists tasks, arms (`traceability` for Shallnot alone, `four-proofs` for
Shallnot and the three modules), repetitions and a seed that orders the runs. The
same runner runs every combination, one session at a time. The committed
configuration asks for one run.

## Tests

`tools/canary/internal/demoloop` holds the tests:

- the renderer and the configuration;
- the runner with the engine, the session and the window replaced by fakes: the
  docker commands of every step, the token on standard input only, the records
  and their token scan, and the window checked before each session;
- the egress proxy, the container entry and the docker command lines;
- a check of the fixture with the real binaries and no model. With the task done
  and the tests unchanged, the gate blocks on a surviving mutant of BOX-2 alone,
  its end-of-turn message names the example `ticket_price(age=65) => 8` and no
  mutant code, and once the test reaches age 65 it passes. A simulated Claude Code
  serves every ticket through the modules' real hooks and executor servers with
  recorded answers. `go test ./internal/demoloop/fixturegate -update` re-records
  those answers from the project's honest host.

The container tests run on the engine and make no model call:

```
demo/loop/run test-containers
```

They build the Linux product and the image, then check that the session's
container shows an empty HOME, no SSH agent, no docker socket and no other socket,
reaches no host but through the proxy, and reaches through it the model endpoint
alone; that the token never shows in `docker inspect`, in the engine's logs or in
a record; that the fixture's check above blocks and then passes inside a
container with no network; and that the runner, with a simulated Claude Code in
place of the CLI, runs a whole session in containers and removes them. The engine
stops when they end. Elsewhere these tests skip.
